# Headlamp Theme Builder Release Guide

This guide is for maintainers releasing a new version of the Headlamp Theme Builder plugin.

For user-facing installation steps for generated theme plugins, see
[`THEME_PLUGIN_GUIDE.md`](THEME_PLUGIN_GUIDE.md).

## Release Flow

Releases are driven by `.github/workflows/plugin-release.yml`.

The workflow:

1. Reads the release version from the git tag, for example `v1.1.0`.
2. Updates release metadata with `scripts/prepare-plugin-release.mjs`.
3. Runs plugin validation.
4. Builds and packages the plugin.
5. Calculates the packaged tarball SHA256.
6. Updates `headlamp-plugin/artifacthub-pkg.yml` with the final archive URL and checksum.
7. Publishes the GitHub release.
8. Pushes the release metadata commit back to `main`.

## Before Releasing

Make sure the working tree contains the intended feature and documentation changes.

Run the local checks:

```bash
npm run build
cd headlamp-plugin
npm run lint
npm run tsc
npm run test
npm run build
```

Update `CHANGELOG.md` under `## Unreleased` with the user-facing release notes. Do not manually rename `## Unreleased`; the release workflow does that from the tag version.

## Create a Release

Create and push a semantic version tag:

```bash
git tag v1.1.0
git push origin v1.1.0
```

The workflow derives `1.1.0` from `v1.1.0`.

## Manual Workflow Dispatch

The workflow also supports manual dispatch with a `version` input.

Use this only when you want GitHub Actions to prepare and publish a release without relying on a pushed tag event. Enter the version without the leading `v`, for example:

```text
1.1.0
```

## Files Updated by the Workflow

The release workflow updates:

- `CHANGELOG.md`
- `headlamp-plugin/package.json`
- `headlamp-plugin/package-lock.json`
- `headlamp-plugin/artifacthub-pkg.yml`
- `headlamp-plugin/README.md`
- `headlamp-plugin/DEPLOYMENT.md`

## Artifact Hub Metadata

Artifact Hub needs the exact release archive URL and checksum.

The workflow updates these annotations in `headlamp-plugin/artifacthub-pkg.yml`:

```yaml
annotations:
  headlamp/plugin/archive-url: "https://github.com/PixelRobots/headlamp-theme-builder/releases/download/v1.1.0/headlamp-theme-builder-1.1.0.tar.gz"
  headlamp/plugin/archive-checksum: "SHA256:<generated checksum>"
```

The checksum is calculated from the tarball generated by:

```bash
cd headlamp-plugin
npm run package
```

Do not edit the checksum manually unless you are replacing the release artifact intentionally.

## After the Workflow Finishes

Check:

1. The GitHub release exists and contains `headlamp-theme-builder-<version>.tar.gz`.
2. `main` has a release metadata commit.
3. `headlamp-plugin/artifacthub-pkg.yml` points at the new release archive and checksum.
4. Artifact Hub shows the new version after its index refreshes.
5. Headlamp Plugin Catalog shows the new version after its cache refreshes.

## If the Workflow Fails

If validation fails, fix the code or docs and push a new commit to `main`, then delete and recreate the tag if the release was not published.

If the GitHub release was published but the final metadata push failed, update the metadata files manually or rerun the workflow after fixing permissions.

If the Artifact Hub checksum does not match, delete the incorrect release artifact and rerun the release from a clean tag. The checksum must match the exact tarball attached to the release.
